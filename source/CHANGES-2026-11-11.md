# Packaging fixes and portable continuation — November 11, 2026

Portable seeding now checks release identity, archive root, duplicate members, the complete manifest file set, sizes and SHA-256 hashes before activating a version. An empty or incomplete ZIP previously could produce an active launcher state without the game executable. Failed copies now leave no partial version and can be retried with a correct archive. Existing version folders are preserved.

Windows release preparation now preserves an existing manifest even when its companion ZIP is absent, and rejects dangling output links and duplicate ZIP members. This matches the existing rule that published release outputs must not be replaced.

The defects were reproduced using pristine November 8 source. The fixed producer tools passed **9 seeding tests and 11 publication tests**, plus the same 9 seeding tests under `python3 -O`. These are temporary-file tests; they do not execute a game or compiler. Native client, transport and engine source are unchanged.

A GitHub-hosted workflow now verifies the source snapshot and exact 28-patch engine reconstruction, builds asset-free native prop/carry/session checks and the networking prerequisites, and runs the launcher, build/support and room Worker suites. This provides independent checks without using the developer's gaming PC. The workflow runs on source pushes and pull requests; it does not package a game or publish a release.

## Native binding capacity and identity

Four actual-bridge CPU regressions were reproduced against the unchanged travel9 source: a duplicate placement identity after the 32nd eligible actor was ignored, a full binding table missed a changed actor instance, a removed actor's slot was unavailable to its replacement until the next discovery, and a changed placement identity retained an obsolete binding.

Patch 29 collects and validates the complete eligible actor set before changing bindings. Duplicate identities, zero instances, malformed trees and more than 32 eligible actors disable prop synchronization for that discovery. Missing or changed bindings are retired before replacements are allocated; exact surviving actor/instance/key bindings retain their native stationary-placement observations. Execute lookup also rechecks the profile and room, allowing the reviewed global-room marker.

The seven focused cases cover these failures, recovery after rejected trees, profile/room changes, other-room exclusion, and 1,000 replacements at full capacity. They use the actual bridge over an owned synthetic arena with network/model paths stubbed. The current source now reconstructs a 29-patch engine; its frozen native-source record describes this CPU candidate.
