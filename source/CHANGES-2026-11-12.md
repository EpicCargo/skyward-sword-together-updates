# November 12 co-op changes

A remote player's reliable scene frame now starts a new local sender incarnation, including a reload of the same area. Previously the receiver cleared queued prop packets but kept accepted ownership and interpolation history. A same-area reload, entrance change, or departure and return between bridge updates could retain an old CARRY/PLACE target, reject the returning stream's lower object sequence and interpolate through old movement samples.

The receiver now renews the affected player's incarnation after validating the complete scene frame. Existing roster and playout logic then retire that stream's accepted targets, replay watermarks and movement history. Other players, the local connection generation and already committed collector rewards remain intact. The protocol and wire format remain version 45.

Validation covers 36 receiver/state/playout cases across small pots, large pots and normal barrels, both CARRY and PLACE. An owned copy of the exact previous receiver reproduces 18 failures with the five intended ownership/playout diagnostics; 18 malformed/unknown-source/reconnect controls pass. Eighteen additional cases use the actual embedded host, TCP receiver, ownership state and movement interpolation.

The actual actor bridge also passed 54 departure/re-entry cases across those three object profiles and host/guest local IDs. They cover floor restoration, rejection of retired packets and old body receipts, same-sequence placement after replacement, local pickup, recycled actors, local reload, active native simulation and preservation of an already placed object. The original 138 deactivation and 42 pause cases, their exact historical baselines, and the existing binding, handback, movement, reconnect and pickup checks remain passing locally under AddressSanitizer/UndefinedBehaviorSanitizer where supported.

These are asset-free CPU/TCP checks. A bounded same-connection soak is a separate gate; its completed receipt, when present, identifies its exact sources. No new Windows gameplay run is claimed. The earlier focused native records identify their different exact tested runtime hashes. Windows execution trust remains unresolved, and the accepted portable, installed game and public update feed are unchanged.

## Discovery-loss candidate

A separate native bridge candidate replaces destructive binding clearing on failed actor discovery with the existing deferred-cleanup path. Packet ownership is still reset and presentation disabled. Only an already outstanding remote carry retains its saved native floor for validation by its exact live actor callback. New fixtures cover overflow, duplicate keys, cycles, bad linkage and the walk limit, alongside local-held, recycled-actor, changed-player, active-state, invalid-model and placed-object controls. Hosted validation passed all 84 candidate cases. The exact patch32 bridge reproduced 36 saved-floor failures; 48 local-held, lifecycle, simulation, model and placement controls passed. The full source suite and Windows runtime cross-build also passed. See `validation/discovery-cleanup-20261112.json`; no new gameplay acceptance is claimed.

## Current native keys and actor lifetimes

Remote packets for absent local objects previously allocated persistent prop tracks. Thirty-two such keys could prevent a currently bound pot from accepting a carry. Native key retirement also left those tracks occupying capacity. The bridge now checks exact current native membership before admitting a remote record and prunes tracks for retired keys after a complete successful discovery. Failed discovery still uses patch33's deferred floor cleanup.

A replacement actor could also inherit an accepted PLACE for the same static placement key. The bridge now retires that accepted transform, retains current-key sender replay watermarks, and fences remote records using their local arrival time. Packets received before or in the same millisecond as a subsequent binding are rejected before updating watermarks. First discovery retains bootstrap delivery of fresh packets that already arrived. Direct local native pickup remains on its native path. Stable bindings keep their targets, replay evidence and applied-placement stamps when another actor changes.

This uses local actor identity and local receive clocks. It adds no cross-client actor lifetime ID or address to protocol45; fresh authenticated logical-key records remain eligible. Native identity is checked again on admission so a change between discovery and queue drain cannot poison the next binding.
