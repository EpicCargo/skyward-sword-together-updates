# November 12 co-op changes

A remote player's reliable scene frame now starts a new local sender incarnation, including a reload of the same area. Previously the receiver cleared queued prop packets but kept accepted ownership and interpolation history. A same-area reload, entrance change, or departure and return between bridge updates could retain an old CARRY/PLACE target, reject the returning stream's lower object sequence and interpolate through old movement samples.

The receiver now renews the affected player's incarnation after validating the complete scene frame. Existing roster and playout logic then retire that stream's accepted targets, replay watermarks and movement history. Other players, the local connection generation and already committed collector rewards remain intact. The protocol and wire format remain version 45.

Validation covers 36 receiver/state/playout cases across small pots, large pots and normal barrels, both CARRY and PLACE. An owned copy of the exact previous receiver reproduces 18 failures with the five intended ownership/playout diagnostics; 18 malformed/unknown-source/reconnect controls pass. Eighteen additional cases use the actual embedded host, TCP receiver, ownership state and movement interpolation.

The actual actor bridge also passed 54 departure/re-entry cases across those three object profiles and host/guest local IDs. They cover floor restoration, rejection of retired packets and old body receipts, same-sequence placement after replacement, local pickup, recycled actors, local reload, active native simulation and preservation of an already placed object. The original 138 deactivation and 42 pause cases, their exact historical baselines, and the existing binding, handback, movement, reconnect and pickup checks remain passing locally under AddressSanitizer/UndefinedBehaviorSanitizer where supported.

These are asset-free CPU/TCP checks. A bounded same-connection soak is a separate gate; its completed receipt, when present, identifies its exact sources. No new Windows gameplay run is claimed. The earlier focused native records identify their different exact tested runtime hashes. Windows execution trust remains unresolved, and the accepted portable, installed game and public update feed are unchanged.

## Discovery-loss candidate

A separate native bridge candidate replaces destructive binding clearing on failed actor discovery with the existing deferred-cleanup path. Packet ownership is still reset and presentation disabled. Only an already outstanding remote carry retains its saved native floor for validation by its exact live actor callback. New fixtures cover overflow, duplicate keys, cycles, bad linkage and the walk limit, alongside local-held, recycled-actor, changed-player, active-state, invalid-model and placed-object controls. ## Current native keys and actor lifetimes

Remote packets for absent local objects previously allocated persistent prop tracks. Thirty-two such keys could prevent a currently bound pot from accepting a carry. Native key retirement also left those tracks occupying capacity. The bridge now checks exact current native membership before admitting a remote record and prunes tracks for retired keys after a complete successful discovery. Failed discovery still uses patch33's deferred floor cleanup.

A replacement actor could also inherit an accepted PLACE for the same static placement key. The bridge now retires that accepted transform, retains current-key sender replay watermarks, and fences remote records using their local arrival time. Packets received before or in the same millisecond as a subsequent binding are rejected before updating watermarks. First discovery retains bootstrap delivery of fresh packets that already arrived. Direct local native pickup remains on its native path. Stable bindings keep their targets, replay evidence and applied-placement stamps when another actor changes.

This uses local actor identity and local receive clocks. It adds no cross-client actor lifetime ID or address to protocol 45; fresh authenticated logical-key records remain eligible. Native identity is checked again on admission so a change between discovery and queue drain cannot poison the next binding.

The actual-bridge fixture passed 72 cases across small pots, large pots and normal barrels with local IDs1/3. The exact patch33 header reproduced 42 intended failures with 30 passing controls. The stress fixture passed 600,000 full-table replacements, preserving 31 stable placements and their presentation stamps per case. Existing 84 discovery-loss, 54 departure, 138 deactivation and 42 pause cases and all historical baselines passed locally under ASan/UBSan. The older roster fixture now creates native actors for all four keys it tests; its stream/watermark assertions are retained.

The earlier one-hour TCP soak covers unchanged client transport sources. The new admission evidence uses synthetic native arenas and model/network stubs; it is not new Windows gameplay, collision or full-client acceptance.

Hosted source validation and the Windows runtime cross-build passed for code commit `42c262235923b9db98f460367b10a8e67a49210b` in [GitHub Actions](https://github.com/EpicCargo/skyward-sword-together-updates/actions/runs/43342088046). The resulting executable was not run on the development PC.

## Reconnect before the world synchronization tick

A reconnect could become online with a new connection generation before the next periodic prop tick. An actor callback could still use the old bridge roster and cached PLACE, send from that stale context, or restore a floor for a previous player incarnation. The callback now checks the current connection generation before using packet authority and invokes the existing suspension path when it differs. Fresh world synchronization reauthorizes the new session.

Pending carry cleanup still validates the exact native actor/player/scene and is consumed once. An already applied placement remains on its ordinary native path, and genuine held linkage is preserved. The change adds no wire fields, remote addresses or new native state writes.

The actual bridge passed 60 session cases across three profiles and local IDs 1/3. The exact patch34 baseline reproduced 24 failures with 36 controls. The new cases invalidate old body receipts like the real renderer and cover pending/settled placements, native pickup, changed player identity, restarted streams, valid floor restoration and repeated callbacks. All earlier native regressions and historical baselines, actual TCP restart/disconnect checks, and another 600,000 full-table replacements also passed locally under sanitizers. These are CPU/stub observations, not new native gameplay acceptance.

## Local player and area at actor callbacks

Patch36 closes the interval before periodic world synchronization notices a local player or area change. The executing actor now checks a fresh local sample against the bridge's player address, player instance and stage/room/layer. A changed or invalid context discards old bindings and scalar authority before reading their target or saved floor. A same-context session loss still uses independently validated once-only cleanup. The checks run again after ordinary native execution, which may cross a safe point, before releasing velocity or sending an observation. Sending also validates the fresh local sample's complete identity.

The exact patch35 header reproduces 60 failures with 36 controls across three object classes and local IDs 1/3. All 96 candidate cases pass under AddressSanitizer/UndefinedBehaviorSanitizer. Coverage includes each local context field, unavailable local data, carry restoration, native-held linkage, context/session changes during native execution, new-world refresh, ordinary placement and pickup, paused cleanup and entrance-only same-area changes. The previously tested post-native area mismatch is retained as a passing baseline control. Earlier native lifecycle matrices and actual TCP restart/disconnect regressions pass. These CPU checks do not establish room/death/reconnect gameplay acceptance.

## Remote ownership at actor callbacks

Patch37 uses the same current roster reconciliation at world ticks and actor callbacks, including after ordinary native execution. Previously an accepted PLACE or CARRY could survive a remote JOIN/SCENE/LEAVE until the next world tick. It could move an object after departure or suppress a higher-ID local pickup announcement. Callback reconciliation now retires that sender's targets and replay state while retaining other live peers, keys and applied placement stamps. Invalid or missing identity suspends prop authority while retaining only outstanding independently validated once-only carry cleanup. World-tick invalid-roster handling uses the same suspension path. No native writes occur during roster reconciliation.

All 108 actual-bridge CPU cases pass across the three supported profiles and local IDs 1/3. The exact patch36 header reproduces 69 failures with 39 passing controls. Coverage includes queued/applied/settled PLACE, visible-body CARRY, same-ID incarnation changes, area departure, late old-tuple packets, native pickup, independent peer placement/replay state, invalid rosters and fresh-session placement. One existing roster fixture now advances its receive timestamp past rebinding instead of expecting acceptance at the deliberately rejected tied millisecond. The presentation fixture permits a test-only custom roster; its default stub is unchanged. These asset-free CPU checks do not establish native departure/reconnect gameplay or independent full clients.

## Returning model guest calls

Patch38 revalidates actor instance, key, native room/state and model identity after each returning native model call. The bridge separately revalidates its captured player/scene/session, binding and exact accepted target before any remaining adapter writes and before velocity release or applied-stamp bookkeeping. No bridge mutex spans a guest/model call.

The adapter distinguishes a rejected presentation that has not started from an interrupted one. An interrupted partial update skips its remaining guest calls and native tail and returns as handled instead of invoking native actor execution twice. A carry marks its saved-floor debt before the first pose write, so settings/session loss, a peer departure or pause during the first model call still permits independently validated once-only cleanup. A newer accepted placement survives an interrupted old carry. Writes already performed before an interruption are not rolled back into possibly changed native memory. Normal no-call barrel behavior and initial validation fallback remain covered.

All 196 CPU cases pass across small/large pots, normal barrels, local IDs 1/3 and each of the three model-call boundaries. The exact patch37 bridge plus native adapter reproduce 156 failures with 40 controls. Cases cover replaced actors/models/keys, genuine pickup, local reload/area change, reconnect/settings changes, remote departure/incarnation changes, invalid models, pause, newer placements, CPU-register preservation and once-only cleanup. Prior native lifecycle and actual TCP regressions pass. These use synthetic native/model/network state and do not establish native gameplay acceptance.
