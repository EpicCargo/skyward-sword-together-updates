# November 13 recompilation and graphics-foundation changes

The existing private Linux game library is complete. Its four generators reached 45,965 `main`, 38,289 `sdk`, 14,146 `subsdk0` and 13,689 `subsdk1` functions and wrote 1,417 generated chunks. Every chunk has a matching object, stamp and empty compile log. Together with four module tables and the game-library entry, all 1,422 link inputs produced the 744,059,728-byte library with an empty link log. Regenerating that library did not restore the missing WSL title UI or scenery, so further game-code recompilation is not the current blocker.

Patch 39 corrects the Vulkan runtime path instead. The guest heap can be much larger than a driver's `maxStorageBufferRange`; the tested software renderer reports 128 MiB while the runtime previously exposed the multi-gigabyte heap as one storage-buffer descriptor. Shaders now receive a 16-byte address/size uniform and access the imported heap through Vulkan buffer-device-address support. Every load/store validates its complete byte span against both the architectural heap and current live import. A real zero-backed fallback keeps the physical reference valid while a zero live size disables unavailable accesses.

The same translator pass now rejects register and constant-buffer operands before indexing fixed arrays. The candidate retained byte-identical MSL output for 7,882 valid translations across 10,000 generated programs, matched 1,990 pre-existing failures, safely rejected 128 malformed vectors and had zero differences. A separate GLSL comparison compiled 1,541 of 2,000 generated programs, retained 441 pre-existing rejections, safely rejected 18 malformed operands and introduced zero new failures. Twelve direct boundary cases and the changed Linux runtime objects also compile and pass.

The address path previously passed nine synthetic software-Vulkan readback cases with zero validation warnings, including reads beyond 128 MiB and complete-span end checks. Later source-only cleanup did not change those address calculations, but that earlier receipt is not treated as final native gameplay acceptance. Patch 39 has not been launched with the game. Windows hardware, WSL title visuals and full co-op gameplay remain separate acceptance gates.

See `validation/recompilation-renderer-foundation-20261113.json` for the aggregate, game-free validation record.

## Complete clean rebuild recipe

Patch 40 fixes the older manual Makefile path. It previously generated and linked only `main` and `sdk`, and its SDK generation address did not match the runtime loader. The recipe now includes `main`, `sdk`, `subsdk0` and `subsdk1` at the exact bases declared in `runtime/rt.h`. This agrees with the already-correct Python game builder and with the four-module private library audit.

A new regression test reads the Makefile and runtime header together, requiring the complete ordered module list, identical bases and one generation command for every module. All three build-tool tests and all six generator tests pass under the guarded CPU runner. A `make -n gen` dry run emits the expected four commands without reading game files or launching the game.
