## Restore texture-handle constant data

Patch47 supplies hardware constant buffer 2 from the current stage's 32 bound 64-bit texture handles, starting at byte `0x20`. Previously the renderers treated that reserved driver buffer as an absent application uniform and uploaded zeros. Vulkan and Metal graphics/compute now snapshot the same stage-local table before transient upload. Indexed reads receive the full 64 KiB constant-buffer span; reserved and unused bytes remain zero. Rebinding or unbinding cannot mutate an earlier uploaded snapshot.

The shared payload fixture covers 35 size, byte-layout, boundary and snapshot-lifecycle cases, including the final slot and upper handle bits, and runs with address/undefined sanitizers in CI. The Windows runtime cross-build covers the actual Vulkan call site; Metal remains unexecuted. This provides the missing handle data but does not implement the separate bindless TEX instruction or establish gameplay acceptance. The discovery came from bounded offline inspection of the user's private shader archive; no game shaders or assets are included here.

## Validate complete shader program headers

Patch46 checks the accessible program length before reading a graphics shader's NVN/SPH headers or subtracting those headers from the available size. Short or null programs now return a translation error; compute programs use their separate header-free minimum. This prevents short graphics programs from reading outside their input or underflowing the instruction-count calculation.

Address/undefined-sanitized CPU checks pass for 614 short/null inputs and 48 valid minimum-size and partial-tail controls across vertex, fragment and compute shaders in both output dialects. The valid controls retain byte-identical source against patch45, whose short-fragment failure is reproduced separately. A broader comparison retains identical MSL for 10,000 generated programs and compiles 1,541 of 2,000 GLSL programs with zero new failures. The regression also runs in CI. This does not implement the separate unsupported bindless texture instruction observed in the opening cinematic.

## WSL game comparison and stencil initialization

The current patch42 Linux runtime built successfully and completed two isolated 1,200-frame game captures with a fresh profile, the existing private game library, match resolution, ordinary A inputs at frames 180/360 and no HD textures/ReShade. Both exited normally. Reviewed captures still show missing title UI and incomplete scenery, so patch39's descriptor correction does not resolve the WSL visual failure.

The validation run logged 500 stencil-operation initialization errors before reaching the callback's logging cap. Patch43 initializes dynamic per-face stencil state even when that draw disables stencil testing, using the existing state cache to avoid redundant commands. Its real 1,200-frame WSL comparison clears those stencil errors, while exposing one separate depth-snapshot readback error. Patch44 gives that diagnostic snapshot the transfer-source image usage required for readback; its native comparison has zero logged validation errors. Neither correction alone restores the missing title UI. See `validation/wsl-visual-stencil-20261113.json`.

The existing private Linux game library is complete. Its four generators reached 45,965 `main`, 38,289 `sdk`, 14,146 `subsdk0` and 13,689 `subsdk1` functions and wrote 1,417 generated chunks. Every chunk has a matching object, stamp and empty compile log. Together with four module tables and the game-library entry, all 1,422 link inputs produced the 744,059,728-byte library with an empty link log. Regenerating that library did not restore the missing WSL title UI or scenery, so further game-code recompilation is not the current blocker.

Patch 39 corrects the Vulkan runtime path instead. The guest heap can be much larger than a driver's `maxStorageBufferRange`; the tested software renderer reports 128 MiB while the runtime previously exposed the multi-gigabyte heap as one storage-buffer descriptor. Shaders now receive a 16-byte address/size uniform and access the imported heap through Vulkan buffer-device-address support. Every load/store validates its complete byte span against both the architectural heap and current live import. A real zero-backed fallback keeps the physical reference valid while a zero live size disables unavailable accesses.

The same translator pass now rejects register and constant-buffer operands before indexing fixed arrays. The candidate retained byte-identical MSL output for 7,882 valid translations across 10,000 generated programs, matched 1,990 pre-existing failures, safely rejected 128 malformed vectors and had zero differences. A separate GLSL comparison compiled 1,541 of 2,000 generated programs, retained 441 pre-existing rejections, safely rejected 18 malformed operands and introduced zero new failures. Twelve direct boundary cases and the changed Linux runtime objects also compile and pass.

The final address path passes 14 synthetic software-Vulkan readback cases with zero validation warnings, including reads beyond 128 MiB, complete-span end checks, exact-end 128-bit stores and rejected overflowing stores. This supersedes the earlier nine-case pre-refactor receipt. The expanded fixture initially used the fallback address for new heap cases; correcting that fixture error produced the passing result without changing the runtime. Subsequent WSL game comparisons confirm that patch39 alone does not restore the missing visuals. Windows hardware and full co-op gameplay remain separate acceptance gates. See [the reproducible GPU test](docs/vulkan-guest-memory-test.md).

## Complete clean rebuild recipe

Patch 40 fixes the older manual Makefile path. It previously generated and linked only `main` and `sdk`, and its SDK generation address did not match the runtime loader. The recipe now includes `main`, `sdk`, `subsdk0` and `subsdk1` at the exact bases declared in `runtime/rt.h`. This agrees with the already-correct Python game builder and with the four-module private library audit.

A new regression test reads the Makefile and runtime header together, requiring the complete ordered module list, identical bases and one generation command for every module. All three build-tool tests and all six generator tests pass under the guarded CPU runner. A `make -n gen` dry run emits the expected four commands without reading game files or launching the game.

## Correct four-module crash symbolization

Patch 41 updates `tools/sym.py`, which still used the obsolete `0x7004000000` SDK base and could not identify addresses in `subsdk0` or `subsdk1`. It now uses the same four names and bases as the runtime loader. The build-tool regression parses the symbolizer configuration without loading private game files and compares it directly with `runtime/rt.h`; all four guarded tests pass.

## Preflight Vulkan adapter requirements

Patch 42 checks the new addressable-guest-memory requirement while choosing a physical device. A Vulkan 1.3 adapter is eligible only when buffer device addresses are supported and one queue can perform graphics and compute work while presenting to the current surface. Discrete/integrated preference and `LARECOMP_GPU` are applied only after those checks, so an incompatible preferred adapter cannot hide a usable fallback and fail later in `vkCreateDevice`.

Eight pure selection cases pass with address/undefined sanitizers, including unsupported explicit selections and queue failures. The actual changed `device.c` compiles under the 512 MiB guard. A read-only WSL probe reports Vulkan 1.4, buffer-device-address support and the same 128 MiB storage descriptor limit behind patch 39; it creates no logical device, window or game process.
